# Platform Admin 审计中心最小可查视图设计

## 1. 背景

桌面端第二份计划已经把运行时审计总线接到平台接口：

- 登录 / 刷新 / 初始化事件会进入本地审计队列
- 聊天生命周期、模型切换、Skill 下载点击、Skill 本地同步等事件会持续上报
- 后端已经把事件写入 `platform_audit_events`

但当前平台管理端仍然没有“看审计”的入口。

这会造成一个问题：

- 桌面端已经在真实上报审计
- 平台数据库已经在真实存储审计
- 但管理端没有最小可查视图，无法完成“平台稳定优先”阶段最基本的闭环验证

因此下一顺序切片聚焦一件事：**把平台管理端审计中心补成最小可查视图**。

## 2. 本次范围

本次只做以下能力：

1. 超级管理员查看平台内某个租户的审计事件列表
2. 租户管理员查看本租户审计事件列表
3. 按最近时间倒序展示审计事件
4. 展示事件类型、账号、租户、发生时间、payload 摘要
5. 管理端最小可用 UI
6. README 与实现文档补齐

本次明确不做：

- 审计导出
- 审计筛选器高级组合
- 分页游标协议复杂化
- 会话中心联动
- 审计统计图表
- 合规只读归档 / 防篡改增强

也就是说，本次只做“先看得到”，不做“审计中心完整版”。

## 3. 角色与权限规则

### 3.1 超级管理员

超级管理员可以：

- 查看指定租户的审计事件
- 当未选租户时，不默认返回全平台海量审计，避免首版查询范围过大
- 需要先选中租户，再读取该租户审计

### 3.2 租户管理员

租户管理员可以：

- 查看自己租户的审计事件
- 不能查看其他租户审计
- 不能查看平台级跨租户聚合视图

## 4. 数据来源与返回模型

继续复用当前 `platform_audit_events` 表。

当前字段：

- `id`
- `tenant_id`
- `account_id`
- `event_type`
- `payload`
- `occurred_at`
- `created_at`

本次后端查询需要补 join：

- 关联 `platform_admin_tenants`
- 关联 `platform_admin_accounts`

返回给管理端的最小记录结构：

- `id`
- `tenant`
- `account`
- `eventType`
- `payload`
- `occurredAt`
- `createdAt`

其中：

- `tenant` 返回 `id / code / name`
- `account` 返回 `id / username / displayName / roleCode`
- `payload` 继续原样返回 JSON，前端只做摘要展示

## 5. 查询规则

### 5.1 返回顺序

- 按 `occurred_at DESC, id DESC` 排序
- 默认只取最近 `100` 条

### 5.2 超级管理员查询边界

- `GET /api/admin/audit/events?tenantId=<id>&limit=<n>`
- 若 `tenantId` 缺失，则返回 `400`，避免无约束全平台扫表

### 5.3 租户管理员查询边界

- `GET /api/admin/tenant/audit/events?limit=<n>`
- 服务端自动绑定当前租户

### 5.4 limit 规则

- 默认 `100`
- 最多 `200`
- 小于等于 `0` 时回落默认值

## 6. 管理端前端设计

### 6.1 超级管理员工作台

新增卡片：

- 标题：`Audit center`
- 行为：
  - 若未选租户，显示提示“Select a tenant to inspect runtime audit events.”
  - 若已选租户，读取最近审计事件
  - 显示事件列表

列表项最小展示：

- 事件类型
- 发生账号
- 发生时间
- payload JSON 摘要

### 6.2 租户管理员工作台

新增卡片：

- 标题：`Tenant audit center`
- 自动加载本租户最近审计事件
- 不显示跨租户切换能力

## 7. 测试策略

至少覆盖：

1. 租户管理员只能查看本租户审计
2. 超级管理员缺少 `tenantId` 时不能读取审计
3. 后端列表按时间倒序返回
4. 超级管理员前端显示审计中心卡片
5. 租户管理员前端显示租户审计中心卡片
6. 定向测试、全量测试、真实 PostgreSQL ignored 测试通过

## 8. 后续演进边界

本次切片只是把“桌面端真实审计上报”接到“平台最小可查视图”。

后续可逐步扩展：

- 事件类型筛选
- 按账号 / 时间范围查询
- 会话中心联动
- 审计导出
- 合规防篡改加强
- 统计看板

这样可以先把“审计能写、也能看”这一基本闭环打通，再继续做合规中心完整版。
