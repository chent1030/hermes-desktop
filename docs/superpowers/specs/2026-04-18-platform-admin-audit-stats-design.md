# Platform Admin Audit Stats Design

## 1. 背景

当前管理端已经能看审计明细，也能做会话联动与多条件筛选，但仍缺一个“先看全局概况，再下钻明细”的视角。

这导致排障时需要直接阅读事件列表，缺少最基础的统计与图表辅助。

## 2. 目标

本次补一个不依赖新接口的最小统计视图：

- 基于当前审计中心已加载的数据生成摘要统计
- 展示总事件数、失败事件数
- 按事件族显示数量与占比条形图

## 3. 方案

### 3.1 数据来源

统计直接基于当前 `auditEvents` 列表在前端计算，不新增后端聚合接口。

### 3.2 统计维度

按以下事件族归类：

- `run`
- `chat`
- `auth`
- `workspace`
- `other`

失败数规则：

- `eventType` 以 `.failed` 结尾即视为失败事件

### 3.3 视图形态

在审计中心筛选表单下方、审计列表上方增加一个摘要区：

- `Total events`
- `Failures`
- 若干事件族统计行

每个事件族统计行展示：

- 事件族名称
- 当前数量
- 一条横向占比条

### 3.4 边界

本次不做：

- 跨页全量统计
- 服务端真实聚合
- 时间趋势折线图
- 点击图表反向筛选

因此该统计区的语义是“当前已加载结果的统计摘要”，而不是全租户全库统计。

## 4. 验证

至少覆盖：

1. 加载审计列表后展示 `Total events`
2. 正确展示 `Failures`
3. 正确展示各事件族数量
4. 切换筛选后统计随当前审计列表更新
