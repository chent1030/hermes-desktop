# 平台桌面端工作区信息入口改造设计

## 1. 背景

当前平台桌面端在用户登录后，会在工作区顶部额外渲染两类平台态信息：

- `WorkspaceBanner`：当审计状态不是 `healthy` 时，在页面顶部显示审计告警横幅
- `workspace-shell-meta`：在顶部显示租户、账号、当前模型、审计状态

这两块内容共同占用了主内容区的垂直空间。对于聊天、会话、技能等高频页面，这种全局顶部信息会持续挤压内容，使页面显得拥挤，也违背了“登录后主界面以任务内容为中心”的桌面工作流体验。

用户明确提出两点要求：

1. 顶部不要再显示审计告警，避免挤压页面
2. 租户、账号、模型、审计状态不要继续放在顶部，最好收进侧边栏新增菜单

因此，这个切片的目标不是修改平台状态本身，而是**重构这些信息在桌面端工作区中的呈现位置与层级**。

## 2. 目标

本次改造只解决一个问题：

**把平台登录态、租户态、当前模型与审计状态从工作区顶部移除，统一收敛到侧边栏新增的“工作区信息”页面中。**

成功标准：

1. 登录后主工作区顶部不再出现审计告警横幅
2. 登录后主工作区顶部不再出现租户 / 账号 / 模型 / 审计状态条
3. 左侧导航新增“工作区信息”入口
4. 用户点击该入口后，可查看租户、账号、当前模型、审计状态和会话相关操作
5. 审计异常只在“工作区信息”页内部表达，不再升级为全局顶部打扰

## 3. 非目标

这一切片不包含以下内容：

- 审计状态计算逻辑变更
- 审计上传 / 重试链路的协议改造
- 工作区主导航结构的大规模重排
- 新增红点、角标、toast 或全局悬浮提醒
- 重新设计整个 Settings 页面
- 修改聊天、会话、技能等业务页面的内容结构

## 4. 现状问题

### 4.1 视觉层级错误

平台状态属于“环境信息”，不是用户每次进入工作区都必须优先看到的“任务内容”。目前它们被放在最顶部，抢占了第一视觉焦点。

### 4.2 审计异常的表达过于全局

`WorkspaceBanner` 采用顶部横幅方式表达异常。即使异常是后台运行态问题，也会影响所有页面的首屏布局。这会让用户在聊天、看会话、管理技能时持续感到被打断。

### 4.3 信息散落，职责不集中

当前平台相关信息分散在：

- `WorkspaceShell` 顶部
- `WorkspaceBanner`
- `Settings` 内的部分平台状态

这使用户缺少一个稳定的一站式入口去查看“当前工作区到底是什么状态”。

## 5. 设计原则

本次改造遵循以下原则：

1. **主界面零打扰**  
   用户登录后的主工作区应默认只呈现导航与当前任务内容，不再被平台状态条和告警横幅挤压。

2. **信息集中收敛**  
   所有平台登录态、租户态、模型态、审计态统一进入“工作区信息”页面。

3. **异常局部表达**  
   审计异常仍然可见，但只在“工作区信息”页面内部呈现，不再升级为全局横幅。

4. **最小行为变化**  
   仅搬迁信息表达位置，不改变登录、刷新会话、重试初始化、审计重试等现有能力语义。

5. **与既有桌面导航一致**  
   复用现有左侧侧边栏导航模式，不新增新的全局容器、浮层体系或顶部导航体系。

## 6. 方案对比

### 方案 A：新增侧边栏“工作区信息”页面（推荐）

把顶部平台状态全部移除，侧边栏新增一个一级菜单“工作区信息”，用户按需进入查看。

优点：

- 完全符合“主界面零打扰”
- 信息集中，入口清晰
- 复用现有导航结构，改动边界明确
- 风险低，容易回归验证

缺点：

- 查看状态需要额外点击一次

### 方案 B：侧边栏新增入口，同时保留侧边栏状态点

优点：

- 能在不占主内容区的前提下提醒异常

缺点：

- 仍然属于被动提醒，和“不要打扰主界面”的要求不完全一致

### 方案 C：改为右侧抽屉

优点：

- 不切换主视图，信息集中

缺点：

- 交互更重
- 与当前桌面端导航结构不一致
- 更像临时补丁，不如独立页面稳定

**最终采用方案 A。**

## 7. 信息架构设计

### 7.1 导航结构

左侧导航新增一个一级菜单：

- `工作区信息`

放置原则：

- 保持在导航下部区域
- 语义上靠近“设置”
- 不与“聊天 / 会话 / 技能 / 工具”这些主任务入口抢首要注意力

### 7.2 页面定位

“工作区信息”页用于集中表达：

- 当前租户是谁
- 当前账号是谁
- 当前平台下发的模型状态如何
- 当前审计链路状态如何
- 当前会话可执行什么平台相关操作

它是一个“环境与状态页”，不是业务操作主页面。

## 8. 页面内容结构

`工作区信息` 页分为四个区块，自上而下排列。

### 8.1 基本信息

展示静态身份信息：

- 租户名称
- 租户代码
- 当前账号显示名
- 当前账号用户名

### 8.2 工作区状态

展示当前运行中的核心状态：

- 当前模型
- 审计状态
- 本地审计状态
- 平台审计状态

### 8.3 审计详情

展示审计链路的详细信息：

- 待上传数量
- 已丢弃数量
- 最近错误

当审计状态为 `buffering` 或 `degraded` 时：

- 在该区块内显示“重试审计上传”按钮

当审计状态为 `healthy` 时：

- 仅显示简洁正常信息，不放冗余说明

当审计状态为 `reauth-required` 时：

- 在该区块内显示高优先级状态说明
- 但仍然只局限在该页面，不恢复全局顶部横幅

### 8.4 会话操作

展示与平台工作区相关的操作入口：

- 刷新会话
- 重试初始化
- 退出登录

其中：

- `退出登录` 放在最下方
- 使用次级破坏性样式，避免误触

## 9. 视觉与交互设计

### 9.1 总体风格

采用克制的企业桌面风格：

- 不新增大色块 banner
- 不新增浮层提醒
- 不做角标闪烁
- 不做全局红点
- 主要通过卡片、分组标题、状态说明来承载信息

### 9.2 审计异常表达

异常不再通过页面顶部整宽横幅呈现，而改为：

- `工作区信息` 页中的状态卡片内部呈现

状态层级：

- `healthy`：中性正常样式
- `buffering`：弱提醒样式
- `degraded`：明显但局部的异常样式
- `reauth-required`：强提醒样式，但仅限本页

### 9.3 导航交互

`工作区信息` 菜单项：

- 与其他侧边栏项使用相同的按钮结构
- 无额外提醒点
- 无默认跳转
- 用户登录后仍按当前默认入口进入主任务页

## 10. 组件边界与代码改造范围

### 10.1 `WorkspaceShell`

移除：

- `WorkspaceBanner`
- 顶部 `workspace-shell-meta`

保留：

- 作为平台工作区最外层容器
- 直接承接 `Layout`

### 10.2 `Layout`

新增：

- 新的导航项 `workspace-info`
- 新的视图分支

职责：

- 负责把“工作区信息”页接入现有左侧导航系统

### 10.3 新页面组件

新增页面：

- `src/renderer/src/screens/WorkspaceInfo/WorkspaceInfo.tsx`

职责：

- 从 `usePlatform()` 读取 `workspace`、`audit`
- 读取 `logout`、`retryInitialization`
- 根据审计状态渲染信息与局部操作

### 10.4 `Settings`

第一阶段：

- 允许暂时保留现有平台状态相关内容，避免改动过大

第二阶段（不在本切片内强制执行）：

- 可再评估是否删除与“工作区信息”重复的平台状态内容，进一步去重

## 11. 迁移策略

采用“两步式最小迁移”：

### 第一步

只做信息搬迁：

- 删除顶部横幅
- 删除顶部 meta 状态条
- 新增侧边栏入口
- 新增 `工作区信息` 页面承接内容

### 第二步

后续如有需要，再评估：

- 精简 `Settings` 中重复的平台状态表达

这样可以保证：

- 改动边界清晰
- 行为变化可控
- 回归成本最低

## 12. 测试策略

### 12.1 `WorkspaceShell` 测试

更新测试断言：

- 不再要求顶部出现审计告警
- 不再要求顶部出现租户 / 账号 / 模型 / 审计状态

### 12.2 `Layout` 测试

新增或更新断言：

- 左侧导航新增“工作区信息”
- 点击后进入新的页面视图

### 12.3 `WorkspaceInfo` 页面测试

需要覆盖：

1. 正常状态下展示租户、账号、当前模型、审计状态
2. 审计异常时，只在该页内部展示异常信息
3. `buffering/degraded` 时展示“重试审计上传”
4. 展示“刷新会话 / 重试初始化 / 退出登录”操作

### 12.4 本地化测试

确认中文文案至少覆盖：

- 导航：`工作区信息`
- 页面标题：`工作区信息`
- 各字段与状态文案

## 13. 验收标准

当以下条件全部成立时，本切片视为完成：

1. 登录后工作区顶部不再出现审计横幅
2. 登录后工作区顶部不再显示租户 / 账号 / 模型 / 审计状态条
3. 左侧导航存在“工作区信息”
4. 点击后可查看租户、账号、当前模型、审计状态
5. 审计异常仅在“工作区信息”页内呈现
6. 会话操作入口在“工作区信息”页可用
7. 主工作流页面可用空间明显恢复，不再被顶部信息挤压

## 14. 最终结论

本次改造的本质，不是删除平台状态，而是**把平台状态从“全局打断型表达”改为“按需查看型表达”**。

最终用户体验应变为：

- 登录后主界面保持干净
- 任务页面不再被顶部提示挤压
- 所有环境与状态信息统一进入“工作区信息”
- 用户需要时再查看，不需要时完全不被打扰
