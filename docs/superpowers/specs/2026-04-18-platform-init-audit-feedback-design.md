# Platform Init And Audit Feedback Design

## 1. 背景

桌面端第二阶段已经接入了租户登录、在线初始化、模型下发、Skill 清单和审计上传主链路，但还有两个影响生产可用性的反馈缺口：

- 初始化失败时，界面直接展示技术错误字符串，缺少按阶段分层的可读提示
- 工作区审计状态当前主要来自本地队列状态，尚未把平台 `/api/audit/health` 探测结果真正并入展示

这会导致：

- 用户知道“失败了”，但不知道失败在 `bootstrap / model / skill` 哪一段
- 当远端审计服务不可用但本地暂时还没有排队事件时，界面仍可能显示“正常”

## 2. 目标

本次一起补齐两个反馈面：

1. 初始化阶段错误分层文案
2. 远端审计健康探测并入工作区审计状态

## 3. 初始化错误分层设计

### 3.1 目标

在不改动现有状态机的前提下，让初始化页在失败时同时给出：

- 失败阶段
- 面向用户的可读说明
- 原始错误文本

### 3.2 分层规则

根据当前运行时错误消息做最小分类：

- 包含 `bootstrap` / `tenant` / `workspace bootstrap`：归为“平台上下文”
- 包含 `model`：归为“模型配置”
- 包含 `skill`：归为“Skill 清单”
- 其他：归为“初始化通用错误”

### 3.3 展示策略

初始化页失败时显示三段信息：

1. 阶段标题，例如“失败阶段：模型配置”
2. 建议动作，例如“平台未下发可用模型，请联系租户管理员或超级管理员检查授权模型与默认模型”
3. 原始错误，例如 `platform default model missing`

双语要求：

- 中文环境显示中文提示
- 英文环境显示英文提示

## 4. 远端审计健康探测设计

### 4.1 目标

工作区轮询审计状态时，不只读取本地队列状态，还要顺带探测平台 `/api/audit/health`。

### 4.2 合并规则

以本地状态为基础，再叠加远端探测结果：

- 本地已是 `buffering`：保持 `buffering`
- 本地已是 `reauth-required`：保持 `reauth-required`
- 本地是 `healthy` 或 `degraded`，但远端健康探测失败：返回 `degraded`
- 远端返回 `401/403`：升级为 `reauth-required`
- 远端健康探测成功：保留本地状态

### 4.3 用户可见效果

工作区横幅和设置页中的“审计状态”将真实反映：

- 本地补传是否堆积
- 远端审计服务是否可达
- 是否已经进入需要重新登录的状态

### 4.4 非目标

- 不修改后台 `/api/audit/health` 返回结构
- 不新增单独的“远端状态字段”
- 不新增复杂健康看板

## 5. 验证口径

至少覆盖：

- 初始化页在模型失败时显示“模型配置”相关提示
- 初始化页在 bootstrap 失败时显示“平台上下文”相关提示
- 审计健康探测接口返回 `503` 时，工作区审计状态降级
- 审计健康探测接口返回 `401` 时，工作区进入 `reauth-required`
